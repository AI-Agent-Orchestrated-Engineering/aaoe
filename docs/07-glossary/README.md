# Glossary

The AAOE Glossary standardizes the vocabulary used across AAOE's
Governance, Operating Model, Standards, Discoveries, Reference
Architectures, Case Studies, and Guides. It does not introduce new
concepts — every definition is derived from existing canonical AAOE
documentation, and each entry cites the documents it was drawn from.

Terms that are used within AAOE documentation but do not yet have a
single canonical definition are marked as **candidates for future
refinement** within their entry, rather than given an invented
definition.

## By Domain

### Engineering

| Term | Summary |
| --- | --- |
| [Specification](specification.md) | Canonical, authoritative engineering guidance derived from approved knowledge |
| [Specification Lifecycle](specification-lifecycle.md) | The governed states a Specification progresses through |
| [Shared Specification](shared-specification.md) | A Specification used to coordinate multiple independent implementations |
| [Specification-Driven Development](specification-driven-development.md) | Defining Specifications before implementation begins |
| [Discovery](discovery.md) | Evidence-based engineering knowledge captured from practical work |
| [Work Order](work-order.md) | The canonical interface between Architecture and Implementation |
| [Architecture Review](architecture-review.md) | Evaluation of completed work against approved architectural intent |
| [Architecture Decision Record (ADR)](architecture-decision-record.md) | The persistent record of an accepted Architectural Decision |
| [Implementation Report](implementation-report.md) | The standard record produced after a Work Order is fulfilled |
| [Engineering Intent](engineering-intent.md) | Objectives, constraints, and expected behavior captured explicitly |
| [Acceptance Criteria](acceptance-criteria.md) | How it will be known that engineering work is done correctly |
| [Constraint](constraint.md) | An explicit boundary on how a Work Order's objective may be achieved |
| [Scope](scope.md) | What is, and is not, included in a Work Order |

### AI Collaboration

| Term | Summary |
| --- | --- |
| [AI Collaborator](ai-collaborator.md) *(candidate)* | Informal term for an AI participating in engineering work |
| [Human Governance](human-governance.md) | Humans review and approve AI-assisted work before it becomes official |
| [Multi-Agent Engineering](multi-agent-engineering.md) | Organizing work across multiple specialized AI agents |
| [Orchestration](orchestration.md) | Coordinating agents' dependencies, sequencing, feedback, and review |
| [Responsibility](responsibility.md) | A specific duty assigned to a role, human or AI |
| [Validation](validation.md) | Confirming that work, or a Discovery, meets its stated criteria |

### Knowledge

| Term | Summary |
| --- | --- |
| [Context](context.md) | The information required for effective engineering collaboration |
| [Context Engineering](context-engineering.md) | Intentionally designing and governing engineering context |
| [Organizational Knowledge](organizational-knowledge.md) | Engineering knowledge that persists beyond the task that produced it |
| [Engineering Memory](engineering-memory.md) *(candidate)* | Preserved reasoning that outlives the people who produced it |
| [Shared Context](shared-context.md) | The common context multiple participants collaborate around |
| [Traceability](traceability.md) | The evidence chain connecting observations to engineering outcomes |

### Architecture

| Term | Summary |
| --- | --- |
| [Capability](capability.md) | A logical function described independently of its implementation |
| [Boundary](boundary.md) | An explicit limit on what a role, capability, or agent may do |
| [Decision](decision.md) *(candidate)* | The act of evaluating evidence and approving a direction |
| [Trade-off](trade-off.md) *(candidate)* | A consequence accepted in exchange for a benefit |
| [Assumption](assumption.md) *(candidate)* | Something taken as true without direct verification |

### Operating Model

| Term | Summary |
| --- | --- |
| [Workflow](workflow.md) *(candidate)* | The preferred ordered sequence of stages for a given practice |
| [Artifact](artifact.md) | Any governed engineering document or output |
| [Lifecycle](lifecycle.md) *(candidate)* | The ordered governed states an artifact or knowledge type progresses through |
| [Governance](governance.md) | How engineering knowledge is created, validated, and evolved |
| [Review](review.md) *(candidate)* | An evaluation of an engineering artifact before acceptance |
