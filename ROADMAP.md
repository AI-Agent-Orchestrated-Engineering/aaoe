# AAOE Roadmap

This roadmap describes the intended evolution of the AAOE ecosystem. It is a
directional plan, not a commitment to fixed dates. Priorities may change through
the human-governed decision process.

## Phase 1 — AAOE Genesis

Establish the canonical knowledge base and its governance.

- [x] Establish founding governance decisions.
- [x] Define the hybrid repository strategy.
- [x] Define the canonical repository taxonomy.
- [x] Create the initial repository structure and contribution workflow.
- [ ] Inventory and classify the existing AAOE working material.
- [ ] Review and approve a migration plan before any source material is moved.
- [ ] Create the initial repository navigation and governance artifacts.

## Phase 2 — Knowledge Foundation

Curate and strengthen the reusable AAOE knowledge base.

- [ ] Establish the standards catalogue and cross-repository navigation.
- [ ] Curate validated discoveries and emerging hypotheses.
- [ ] Publish the operating model, roles, and engineering lifecycle.
- [ ] Document reference architectures and foundational terminology.
- [ ] Prepare the first public case study.

## Phase 3 — Publishing Foundation

Make approved AAOE knowledge clear and accessible to a public audience.

- [ ] Establish the AAOE website repository and publishing workflow when its
  lifecycle warrants separation.
- [ ] Create concise introductory pages derived from canonical knowledge.
- [ ] Publish initial articles and a public-facing case study.
- [ ] Define a repeatable release and publication process.

## Phase 4 — Community

Enable thoughtful external participation.

- [ ] Establish discussion, proposal, and review pathways.
- [ ] Publish reusable contribution templates.
- [ ] Document community governance and a code of conduct.

## Phase 5 — Ecosystem

Demonstrate AAOE through independent, real-world artifacts.

- [ ] Publish reusable templates and agent definitions.
- [ ] Publish reference examples and applied case studies.
- [ ] Expand the ecosystem through repositories with independent ownership or
  lifecycle needs.
